# modern/ — Target Application

## Target stack  <!-- decided by: commissioning team (leadership-ratified), 2026-08 — PB-004 -->
- Language/runtime: Python 3.12+          - Framework: FastAPI
- Database: PostgreSQL 15+                - Key libraries: SQLAlchemy 2 (or asyncpg direct —
  first FREE choice, record it), Pydantic v2, Alembic for migrations, pytest
- Rationale: PB-004 — team expertise; Postgres removes SQLite's single-writer bottleneck
  (cf. OQ-008's unexplained 5xx under load).

## Architecture rules (each cites its motivation)
- **PB-001 (sync SMTP took ticket-closing down):** no network I/O to third systems inside a
  request handler, ever. Side effects that must survive commit go through the transactional
  outbox (`mail_outbox`, target-schema.sql) + worker. Request success must never depend on
  SMTP availability (NFR-1).
- **PB-002 (cleartext MD5 tokens):** secrets are generated by CSPRNG and stored only as
  hashes; token plaintext exists in memory and in the outgoing mail body only (NFR-3).
- **PB-005 (no UI changes):** response shapes are frozen by `docs/contracts/openapi.yaml` —
  including the "wrong-looking" ones (200-`{}`, no pagination, `med` spelling). FastAPI's
  reflex to 422 on validation must be actively suppressed where the contract says otherwise
  (e.g. tolerated non-JSON bodies, TC-1). Do not let framework defaults leak into the
  contract.
- **Harness-first:** `harness-boot.sh`, `harness-dump.sh`, `harness-age-token.sh` (contract:
  `verification/harness/README.md`) are part of this tree and maintained with the app;
  hooks live behind `HARNESS=1` and are absent from production builds.
- **NFR-2:** no route regresses its `perf-envelopes.json` p95.

## Conventions
- Layout: `app/` (routers/, services/, db/, outbox/), `tests/` (unit; cross-tree suites
  live in `verification/`), `alembic/`.
- Errors: contract error bodies are literal — `{"error": "<token>"}` with the exact tokens
  from `docs/contracts/fixtures/errors.json`; framework-generated error pages only where
  the contract records them (status + media-type fidelity).
- Time: store timestamptz; serialization format chosen in WO-001 (record as FREE choice);
  historical-data conversion policy is OQ-005's ruling — do not guess.
- Config via env vars (`TICKETD_DB_URL`, `TICKETD_SMTP_HOST`, `HARNESS`); no config files
  with secrets.
- Naming: keep legacy's domain vocabulary (`docs/domain/glossary.md`) — `med` not `medium`,
  `open/closed` not new states.
